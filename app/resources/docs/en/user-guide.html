SAI Statistics — User Guide

SAI Statistics is a cross-platform desktop statistics application built on the R engine. This guide covers the core workflows and the points worth knowing if you are coming from SPSS.

1. Importing and Saving Data

Use File ▸ Import Data to open CSV/text, Excel (.xlsx), SPSS (.sav, .zsav, .por), Stata (.dta) or SAS (.sas7bdat, .xpt) files. The data is written straight into the app's built-in database — there is no separate loading step to wait through, even for large files.

More than 200,000 rows: Data View shows the whole dataset without pagination. After importing a larger dataset you will see an information box — it is only a heads-up and blocks nothing. Scrolling may become slower, but analyses are unaffected: every analysis reads directly from the database, not from what Data View is displaying.

File ▸ Save stores your work in the app's own .sdf format — data, variable definitions and cell formatting in a single file, so reopening it needs no import step. File ▸ Export Data writes CSV, Excel or SPSS (.sav) files.

2. Variable View — What Actually Affects Analyses?

An important note for users coming from SPSS: some Variable View fields are purely cosmetic, while others genuinely change analysis results. The table below shows which is which.

Field Effect Details
Missing (user-defined missing values) ✅ Real The missing-value codes you define (e.g. -99) are excluded from that variable's statistics in the analyses.
Decimals ✅ Real (display) Controls the number of decimals shown for values, e.g. in the Frequencies table.
Measure (Nominal / Ordinal / Scale) 🟡 Partial Moves variables of the matching measurement level to the top of the variable lists in dialogs. It is not a filter — you can still pick any variable.
Role 🟡 Partial Pre-fills the target and input boxes once, the first time some dialogs are opened.
Width ❌ Cosmetic Only changes how Data View displays cells; it never affects results.

Bottom line: take missing-value definitions seriously — they are the fields that change statistical results. The others mainly keep the familiar SPSS layout.

3. Weight Cases / Split File / Select Cases

Once switched on in the Data menu, these three settings apply automatically to every analysis that follows — you don't need to set them again in each dialog:

  • Weight Cases: core analyses such as Frequencies, Crosstabs, Descriptives, Means, the t tests and ANOVA use true weighted formulas (not row duplication). An analysis that does not support weighting says so with a warning in its output instead of silently ignoring the weight.
  • Split File: produces separate results for each group where the analysis supports it; otherwise the output shows a warning.
  • Select Cases: limits the rows that every analysis reads.
If a result looks different from what you expected, check the status bar first: it always shows the weight, split and filter state (for example Filter: ON).

4. Running an Analysis

Choose a procedure from the Analyze menu, move variables into the target boxes by drag-and-drop or double-click, open sub-dialogs such as Statistics or Options if needed, and click OK. The result appears in Output View. Every dialog also offers:

  • Paste R — shows the R code that will run (full transparency).
  • Paste Syntax — writes the equivalent SPSS syntax command into the Syntax / Terminal tab, so you can save and re-run it later.
  • Keyboard: Tab/Shift+Tab moves between fields, Enter confirms, Escape cancels.

5. Output — Formats and Export

Every block in Output View can be collapsed or removed. The table style (Academic / Compact / APA) is set in Edit ▸ Preferences. File ▸ Save Output as HTML... creates a single self-contained HTML file that you can share by e-mail; File ▸ Export Output saves the results as HTML, PDF, Word, Excel, CSV or Markdown.

6. Syntax / Terminal Tab

The Syntax / Terminal tab (Ctrl+5) has two modes:

  • SPSS Syntax mode: write classic SPSS commands such as FREQUENCIES VARIABLES=age. They run through the same analyses and the same input checks as the menus — no arbitrary code is executed.
  • R Console mode: an interactive R session, similar to RStudio. Code runs only on your own computer and only when you click Run — nothing runs automatically, even if an opened file contains code. You can turn the console off under Edit ▸ Preferences ▸ Enable the R console.

7. Accessibility

Keyboard navigation (Tab/Enter/Escape, focus kept inside dialogs), a High Contrast theme and screen reader support (live regions, ARIA roles) are available in all dialogs and in Output View. Data View and Variable View are HTML grids with ARIA roles, so screen readers can read their cells, and Output tables are real HTML tables.

Tip for large datasets: to stay fast, Data View draws only the rows currently on screen. To review a large dataset with a screen reader, summarize it with Frequencies or Descriptives and read the tables in Output View rather than moving cell by cell.
